## P0

### P0-1 「取消」按钮是假的（且没有任何"停止"入口）

| 字段 | 内容 |
|---|---|
| 优先级 | P0 |
| 问题描述 | 处理 fuji.mp4 时点「取消」，状态栏变成"正在停止…（等待当前步骤完成）"，**进度继续走、worker 继续跑**；57 秒后处理照常完成并弹出核验窗口（我明明点了取消）。用户会以为"点了取消 = 稍等一下就好"，实际是白等一轮。同理：AI 分析没有停止按钮（`analyze_rows` 有 `stop_flag` 参数但没接）；处理中关闭主窗口直接 `worker.terminate()`，无确认、可能留下半截临时文件。 |
| 改进方案 | 1. 给 `pipeline.process` 增加 `should_stop: callable` 参数，在阶段边界 + 抽帧/切分/去重循环里检查；2. `Worker.run` 传 `self.isInterruptionRequested`；3. `_cancel()` 改为 `worker.requestInterruption()` + 按钮立即禁用并显示"正在停止…（当前帧处理完即停）"，同时**再点一次可强制结束**（`terminate` + 提示会中断）；4. 完成回调若发现已请求中断则丢弃结果、不弹核验窗口，状态栏提示"已停止（未生成结果）"；5. `closeEvent` 处理中弹"处理尚未完成，退出会丢失当前进度"，确认后再 requestInterruption + wait(5s)，仍不退再 terminate；6. AI 分析同一套：`BarReader` 接 `stop_flag`，核验页给「停止 AI」按钮。 |
| 涉及代码 | `gui_qt.py:443 MainWindow._cancel()`、`gui_qt.py:518 closeEvent()`、`gui_qt.py:184 Worker.run()`、`pipeline.py:236 process()`、`vlm_recognize.analyze_rows(stop_flag=…)`、`gui_qt.py:823 BarReader` |

### P0-2 核验窗口打开时长时间"假死"

| 字段 | 内容 |
|---|---|
| 优先级 | P0 |
| 问题描述 | 处理完成后窗口**要等好几秒到几分钟才出现**，期间主窗口也无法操作（同一个 UI 线程）。实测：24 行 2.85s、49 行 14.1s 和 26.3s（两次）、200 行 **212.4s**。原因是 `ReviewWindow.__init__` 里同步调 `_compute_similar()`，对每对行做全分辨率 `cv2.resize` + `int16` 逐像素比较（900×470 量级），复杂度 O(n²)；`_recover()`、`_import_image()`、`_on_clean()` 之后也会再跑一次（25 行约 3s，界面再次僵住）。用户视角：点完「开始处理」……然后程序好像死了。 |
| 改进方案 | 1. `__init__` 里先 `show()`，把 `_compute_similar` 用 `QTimer.singleShot(0, …)` 或 `QThread` 放后台，完成后 `_render_list()` 刷新；期间导航行右侧显示"正在检测重复行… 0/300 对"；2. 算法降阶：先用现有 `row_fingerprint`（很便宜）筛出候选对，再对候选做**缩到 320px 宽 + 灰度**的逐像素比较；3. 结果写 `work_dir/similar_cache.json`（key 用 `(source,index)`），重开核验/找回行时直接复用；4. 300 对以上按分块让出事件循环（每 50 对 `QApplication.processEvents()`），至少让"取消/关闭"可点。 |
| 涉及代码 | `gui_qt.py:899 ReviewWindow._compute_similar()`、`gui_qt.py:784 __init__`（第 796 行调用）、`gui_qt.py:1876 _recover()`、`gui_qt.py:1893 _import_image()`、`gui_qt.py:1692 _on_clean()` |

### P0-3 AI 全线失败，界面却显示"AI 分析完成"

| 字段 | 内容 |
|---|---|
| 优先级 | P0 |
| 问题描述 | 用当前 `vlm_config.json`（provider=deepseek，model=deepseek-flash）点「AI 识别 + 去重」，3 行只花 2 秒就结束，状态栏写 **"AI 分析完成：3 行｜碎片/空谱 0 行｜疑似重复 0 组"**，但列表里没有任何和弦/歌词摘要（截图 `71_当前版_AI整体失败却显示完成.png`）。单行探针显示真实错误是 `HTTPError 400 Bad Request`。两个根因：①`BarReader.run` 调 `analyze_rows(...)` **没有传 model**，`_call` 于是用 `DEFAULT_MODEL="qwen3-vl-plus"` 发到 `api.deepseek.com` → 400；②`vlm_recognize.work()` 把所有异常吞成 `{}`，`_post_once` 对 400/5xx 抛的是 `requests.HTTPError`（不是 RuntimeError），`_call` 的降级链也不会触发。结果 AI 一次都没成功，界面却报告"完成、0 问题"，比报错更危险——用户会以为自己不用再核验。 |
| 改进方案 | 1. 调模型：`BarReader.run` 用 `analyze_rows(self.rows, model=load_model(), …)`，`pipeline._process_horizontal` 同理；2. 让失败可见：`analyze_rows` 返回 `(results, failed, total)` 或把失败行标在 dict 里，`_on_ai_done` 若 `failed>0` 用**橙色状态条**显示"AI 失败 N/M 行（模型：deepseek-flash）—— 结果不完整，请手动核验"，并弹一次带"详情"的提示；若 `failed==total` 显示"AI 未返回任何结果"而不是"完成"；3. `_post_once` 把 400/5xx 转成 `RuntimeError(f"HTTP {code}: {body[:200]}")`，走已有降级链；4. 设置页「测试连接」改发**一张真实行图**（不是文本 "hi"），否则测不出"模型不支持图片"这类错误；5. 主窗口 AI 状态旁显示最近一次调用结果（成功/失败原因），不要只藏日志。 |
| 涉及代码 | `gui_qt.py:709 BarReader.run`、`gui_qt.py:872 _on_ai_done`、`vlm_recognize.py:131-150 work()/analyze_rows`、`vlm.py:275 _post_once`、`vlm.py:325 _call`、`gui_qt.py:635 ApiSettingsDialog._test` |

### P0-4 导航方块漏行、组错位

| 字段 | 内容 |
|---|---|
| 优先级 | P0 |
| 问题描述 | 导航区本应"每行一个方块"，但只要重复组成员**不相邻**（AI 判重恰恰经常如此：副歌在视频后段重复），`_refresh_nav_grid` 里 `i = groups[gi][-1] + 1` 会把组首到组尾之间的**所有行直接跳过**。实测：25 行、组 `[[2,22],[4,24]]` → 只有 **6 个方块**，第 4–22 行完全没有方块（截图 `65_当前版_整体_缺行.png`，容器只有 130×20）；49 行 → 30 个方块；200 行 → **52 个方块**（148 行没有导航）。另外组内方块被拉在一起连续排列，方块顺序 ≠ 列表顺序，点第 4 个方块可能跳到第 23 行。 |
